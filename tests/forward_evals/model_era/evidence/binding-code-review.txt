## 결론: 조건부 수정 필요 (LGTM 아님)

표 삭제 자체는 canonical grading(`official_practice_material.can_be_sole_basis: false`, `use_allowed: support_or_context`)과의 불일치를 실제로 제거했고, 고정 문구·중복 산문 요구도 사라졌습니다. 다만 아래 항목은 병합 전 처리 권장입니다. 아래는 텍스트 정합성 검토이며 **모델 실제 거동은 UNMEASURED**, 법률 자문·전문가 인증이 아닙니다.

### 1. (요청 사항 직격) 사용자가 직접 제시한 사실이 독립 조사 대상으로 흡수될 여지 — 중간

새 문장은 `필수 근거·사실·적용 범위가 미확인·stale이거나`로 **"사실"을 결론 구속 축에 편입**했습니다. 구 표는 authority 상태만 구속했으므로, 이는 신설된 구속입니다. 그런데 "사실"에 대해 *사용자가 진술한 전제*와 *외부 확인이 필요한 사실*의 구분이 없습니다.

- `가능한 조건부 분석·초안에는 그 전제와 다음 확인 대상을 남긴다`가 부분 완화이지만, 앞 절은 "미확인이면 한정·유보"를 무조건으로 읽힐 수 있어, 사용자가 명시한 직원 수·계약일·통지일 같은 직접 사실에도 유보/재확인 요구가 붙는 과잉 헤지를 유발할 수 있습니다.
- 제안(1문장 이내, 절차 추가 없음): "사용자가 직접 제시한 사실은 전제로 수용하고 전제임만 표시하며, 확인 대상은 authority와 사용자가 제시하지 않은 사실에 한정한다."

### 2. 위임 대상 문서의 downgrade 규칙이 같은 모호성을 상속 — 중간

`citation-verification-contract.md`의 `사용자가 제공한 조문번호, 사건번호, 금액, 기한을 독립 확인하지 않았다`는 **법정 금액·기한**과 **사용자 자신의 사건 사실(지급액, 통지일)**을 구분하지 않습니다. 이번 diff로 research-workflow가 이 계약에 결론 구속을 위임하면서 이 문구의 하중이 커졌습니다. `법정 금액·법정 기한 등 법률 근거 성격의 값`으로 범위를 좁히는 표현 수정 권장.

### 3. `공식 원문: 하급심` 라벨의 산문 정의 소실 — 중간

삭제된 표는 `공식 원문: 하급심`을 언급하던 몇 안 되는 위치였습니다. 위임처인 `source-grading.md`의 「라벨 정의」 표에는 이 라벨 행이 **없고**(로컬 미러: 하급심만 존재), YAML `official_primary_lower_court`와 `default_labels`("법망 API — 판례 (하급심)")에만 존재합니다. 위임 구조상 사람이 읽는 단일 소스에 라벨이 누락되므로 `source-grading.md` 라벨 정의 표에 1행 추가 필요.

### 4. `[CONTRADICTED]` 태그 부착 의무의 참조 순환 — 낮음

새 문장은 "근거가 상충하면 한정·유보"만 남기고 태그 노출 의무를 제거했습니다. 의무는 `source-grading.md` 규칙 5에 남아 있으나, 그 규칙은 다시 `research-workflow.md#legal-verification-core`의 conclusion binding을 가리켜 순환 참조가 됩니다. `legal-verification-core`의 contradiction scan이 `[CONTRADICTED]` 부착을 실제로 명시하는지 확인하고, 아니라면 `source-grading.md` 규칙 5의 역참조 대상을 조정하십시오.

### 5. 정적 검사 관련 — 낮음

- `load_yaml(...)["source_classes"]`와 `source_classes[source_class]` 직접 인덱싱은 키 소실 시 `AssertionError`가 아닌 `KeyError`로 실패합니다. 다른 정책 검사와 실패 표면이 다르면 `.get` + 명시적 assert로 통일 권장.
- 에러 메시지 `must not become a sole legal basis`가 `use_allowed` 불일치까지 포괄하지 못합니다. 두 조건 중 무엇이 깨졌는지 드러나도록 메시지 분리 권장.
- 삭제된 `assert_not_contains`(미확정 실무자료가 VERIFIED 상단 행으로 재등장 방지)의 대체 가드가 없습니다. 표가 사라져 재발 확률은 낮지만, 정확 문구 테스트를 피하려면 `section_body("### Conclusion binding")`에 `[VERIFIED]`와 `공식 실무자료`가 동일 결론-허용 문맥으로 다시 묶이지 않는지 정도의 최소 negative 가드는 유지 가능합니다.
- 함수명 `check_current_law_verified_binding_excludes_unconfirmed_practice_material`이 실제 검증 내용(구조화 정책 값 + 참조 링크)과 어긋납니다. 개명 또는 분리 권장.

### 6. 병합 전 확인 필요(도구 없이 검증 불가) — 낮음

삭제된 문자열(`확인한 범위에서는 …`, `가능성이 있으나 원문/공식 확인 전 단정 불가`, `stale 자산만 있음` 등)을 다른 테스트나 `output-formats.md`/`SKILL.md`가 인용·assert하고 있지 않은지 확인하십시오. 이번 diff는 테스트 1개만 갱신했습니다.
