# SDK 교체 검토 메모 (초안)

- 검토일: 2026-09-08
- 대상: 커머스 앱 광고 SDK 교체, 맞춤형 광고 철회, 성능 계측 병행
- 독자: 앱팀, 개인정보 담당
- 기준: 제공된 발췌만. 공식 사이트 실시간 확인 아님. 2026-09-11 예정법은 적용하지 않음.
- 회사 맥락: 미설정 — 한국법 일반 기준

이 문안은 내부 검토용 초안이다. 이용자 고지, 벤더 통지, 처리방침 게시, 계약 서명처럼 대외 효과가 있는 문서는 별도 검토 후 보낸다.

---

## 1. 지금 증거로 말할 수 있는 것

화면의 철회 완료와 신규 SDK 광고 설정 꺼짐만으로는, 맞춤형 광고 목적 처리가 서버·벤더 단까지 멈췄다고 보기 어렵다. 서버 수신기가 구매 이벤트를 새 벤더로 보낼 수 있다는 점과, 이번 점검에서 실제 전송 로그를 받지 못한 점이 남아 있다.

벤더의 “suppression 적용 완료” 회신도 대상 식별자, 목적, 적용 시각이 없어, 철회한 이용자에 대한 목적 제한이 끝났다고 확정할 수 없다. 계약상 벤더의 독자 광고 최적화 허용 여부도 미확인이다.

반대쪽의 “모든 이벤트와 모든 보존 데이터를 즉시 삭제해야 한다”는 주장도, 제공된 법령 발췌만으로는 뒷받침되지 않는다. 제공 자료에 파기 조문(제21조) 본문이 없다. 광고 철회가 확인된 비식별 집계 계측까지 중지·삭제하라는 근거도 없다.

성능 계측은 개인·기기 식별자 없이 재식별할 수 없는 집계값만 내부에서 처리하고 외부 벤더 전송이 없다는 사실이 확인됐다. 이 경로는 맞춤형 광고 철회와 분리한다.

---

## 2. 사실관계 (이번 점검 범위)

| 항목 | 확인 상태 |
|------|-----------|
| 이용자가 맞춤형 광고를 끄면 화면에 철회 완료 표시 | 확인 |
| 같은 조작으로 신규 SDK 광고 설정도 꺼짐 | 확인 |
| 서버 기존 이벤트 수신기가 구매 이벤트를 새 벤더로 전송할 수 있음 | 가능 상태로 확인 |
| 철회 후 실제 전송 로그 | 이번 점검에서 미확보 |
| 벤더 suppression 회신 | “적용 완료”만 있음. 식별자·목적·시각 없음 |
| 계약상 벤더 독자 광고 최적화 | 미확인 |
| 성능 계측: 식별자 없는 내부 집계, 외부 전송 없음 | 확인 |

구매 이벤트에 어떤 식별자가 붙는지는 이번 자료에 없다. 이벤트 항목을 확인하기 전에는 개인정보 해당 여부를 단정하지 않는다.

## 3. 광고 철회와 성능 계측을 나누는 기준

맞춤형 광고 SDK와 내부 성능 계측은 같은 “이용 기록”이 아니다. 식별 가능성과 외부 제공 여부로 나눈다.

제공된 정책방안은 행태정보의 개인정보 해당을 이렇게 나눈다.

1. 이용자 식별자를 매개로 회원정보와 결합하면 개인정보에 해당할 수 있다.
2. 난수 식별자라도 행태정보에 명백한 개인정보가 있거나, 누적·중첩·결합으로 특정 개인을 알아볼 가능성이 있으면 개인정보에 해당할 가능성이 높다.
3. 난수 식별자이고, 행태정보에 개인정보가 없으며, 시간·비용·기술을 합리적으로 볼 때 다른 정보와 쉽게 결합해 특정 개인을 알아볼 수 없으면 개인정보로 볼 수 없다.

**[공식 실무자료] [VERIFIED: 정책방안 해당 설시]** — 제공된 「맞춤형 광고에 활용되는 온라인 행태정보 보호를 위한 정책 방안」(2024.1) PDF 22쪽 발췌. 직접 공식 사이트 확인 아님.

같은 문서는, 개인을 식별해 처리하면 보호법상 의무를 따르고, 식별하지 않고 처리하려면 누적·중첩·결합으로 식별 가능성이 생기지 않게 해야 한다고 적는다. 비식별 처리에서는 개인정보 시스템과 행태정보 시스템을 분리하고 매칭키를 두지 말 것을 의무로, 처리방침 공개·사후 거부·안전조치는 권고로 구분한다. 맞춤형 정보추천은 맞춤형 광고에 포함되지 않는다고 적혀 있다.

**[공식 실무자료] [VERIFIED: 정책방안 해당 설시]** — 같은 문서 PDF 25~26쪽. 직접 공식 사이트 확인 아님.

이번 점검에서 확인된 성능 계측은 위 3번에 가깝다. 식별자가 없고, 재식별할 수 없는 집계이며, 내부만 처리하고 벤더로 보내지 않는다. 맞춤형 광고 철회는 광고 목적의 식별·결합·외부 전송을 멈추는 문제이지, 확인된 내부 집계 계측을 함께 끄라는 의미가 아니다.

다만 이 구별은 지금 확인된 사실에 한정한다. 이후 기기·광고 식별자를 붙이거나, 집계 전 원본을 광고 벤더에 보내거나, 광고 프로필과 매칭하면 경로를 다시 본다.

정책방안이 제15조·제22조·제30조·제31조·제37조를 적시하는 부분은, 그 조문 본문이 이번 법령 발췌에 없는 것은 조문 내용까지 [INSUFFICIENT]이다. 제15조 본문만 아래 법령 발췌로 확인했다.

## 4. 두 주장에 대한 검토

### 제품팀: 화면과 벤더 회신이면 충분하다

충분하지 않다.

철회는 정보주체가 광고 목적 처리를 멈춘다는 의사표시다. 클라이언트 설정이 꺼진 것과, 서버가 구매 이벤트를 새 벤더로 보낼 수 있는 상태는 별개다. 전송 로그가 없으면 철회 이후에도 이벤트가 나갔는지 확인할 수 없다.

벤더 회신은 대상·목적·시각이 없다. 누구의 어떤 식별자를, 맞춤형 광고 목적에 한정해, 언제 멈췄는지 복원할 수 없다. 이 상태로는 목적 외 이용 금지와 수탁자 감독을 충족했다고 보기 어렵다.

제공된 법령 발췌상 위탁이면 문서로 목적 외 처리를 금지하고, 수탁자는 위탁 범위를 넘어 이용하거나 제3자에게 제공하면 안 된다. 위탁자는 처리 현황 점검 등으로 감독해야 한다.

```text
제26조 ① 위탁은 다음이 포함된 문서로 한다.
  1. 위탁업무 수행 목적 외 개인정보의 처리 금지
  2. 기술적·관리적 보호조치
  3. 그 밖에 대통령령으로 정한 사항
④ 위탁자는 수탁자를 교육하고, 처리 현황 점검 등 대통령령으로 정하는 바에 따라
   수탁자가 개인정보를 안전하게 처리하는지를 감독하여야 한다.
⑤ 수탁자는 위탁받은 업무 범위를 초과하여 이용하거나 제3자에게 제공하여서는 아니 된다.
```

**[제공된 법령 발췌] [VERIFIED]** — 개인정보 보호법 제26조 제1항·제4항·제5항. 법률 제20897호, 시행 2025-10-02. 제공 발췌 확인(직접 공식 사이트 확인 아님). 대통령령 점검 방법·주기는 이번 자료에 없음.

광고·판매 권유 위탁이면 수탁자 변경 시 정보주체에게 알려야 한다.

```text
제26조 ③ 재화 또는 서비스를 홍보하거나 판매를 권유하는 업무를 위탁하는 경우
위탁 업무의 내용과 수탁자를 정보주체에게 알려야 한다.
위탁 업무의 내용이나 수탁자가 변경된 경우에도 또한 같다.
```

**[제공된 법령 발췌] [VERIFIED]** — 같은 발췌, 제26조 제3항.

이번 자료만으로는 새 광고 SDK가 위탁인지 제3자 제공인지를 확정하지 못한다. 제17조 본문이 발췌에 없다. 분류는 남은 확인으로 둔다. 위탁으로 보면 제26조 제3항 고지 여부가 출시 전 쟁점이다.

정책방안은 맞춤형 광고를 거부한 기기·웹·앱에 대해 다른 방식으로 맞춤형 광고용 온라인 식별자를 생성하는 것을 금지하고, 거부 우회(디지털 지문 등)도 금지한다고 적는다. 이 문장은 사후 통제권 항목 아래 “권고” 표제와 함께 있다. 법령 제37조 본문은 이번 발췌에 없으므로, 우회 금지를 현재법 조문 효과로 승격하지 않는다. 실무상으로는 철회 후 서버 이벤트·새 식별자·벤더 측 재프로파일링이 우회가 되지 않는지 로그로 확인하는 편이 맞다.

**[공식 실무자료] [VERIFIED: 정책방안 해당 설시]** — 정책방안 PDF 26쪽. 제37조 본문 미제공.

### 다른 담당: 모든 이벤트와 모든 보존 데이터를 즉시 삭제해야 한다

제공 자료로는 그렇게 단정하지 않는다.

확인된 의무의 핵심은, 식별 가능한 행태·구매 이벤트를 맞춤형 광고 목적으로 계속 쓰는 것을 멈추고, 그 멈춤을 서버·벤더에서 증명하는 것이다. “모든 이벤트”와 “모든 보존 데이터”의 즉시·전부 삭제를 명하는 조문은 이번 법령 발췌에 없다. 파기 기한·범위도 없다.

생성형 AI 안내서는 학습데이터 옵트아웃 이후 수집 중지, 삭제 기능 제공을 사례·권고로 적는다. 대상은 생성형 AI 학습이며 광고 SDK가 아니다. 안내서 권고를 법정 즉시 전부 삭제 의무로 바꾸지 않는다. PDF 50쪽 체크리스트도 원본은 법적 의무와 자율 이행을 색으로 구분하나, 이번 텍스트에는 색이 없어 항목 전부를 법적 의무로 보지 않는다. 점검 주기·필수 양식으로도 고정하지 않는다.

**[공식 실무자료] [VERIFIED: 안내서 해당 설시 / 법령 의무로 미승격]** — 「생성형 인공지능(AI) 개발·활용을 위한 개인정보 처리 안내서」(2025.8) PDF 46·50쪽.

광고 철회 범위에서 지울 대상과, 지워서는 안 되는 대상을 나눠 적는 편이 맞다.

| 구분 | 철회 후 취급 | 이번 자료 근거 |
|------|----------------|----------------|
| 맞춤형 광고 목적의 식별자·행태·구매 이벤트, 벤더 측 광고 프로필 | 목적 사용 중지. 전송 여부·suppression 범위·잔존 데이터를 확인한 뒤 목적별 삭제·분리 | 제26조 목적 외 금지·감독. 정책방안의 거부 후 식별자 우회 금지 설시 |
| 확인된 내부 성능 집계(식별자 없음, 재식별 불가, 외부 미전송) | 광고 철회만으로 중지·삭제하지 않음 | 정책방안 사례 ③ 취지, 확인된 사실 |
| 계약 이행·정산·법령상 보관이 필요한 구매 기록 | 광고 목적과 분리. 광고 철회를 이유로 일괄 삭제하지 않음 | 제15조 제1항 제4호는 계약 이행 수집·이용 근거를 두나, 보관 기간 본문은 이번 발췌에 없음 [INSUFFICIENT] |
| 벤더가 자기 광고 최적화에 쓰는 복사본 | 계약상 허용 여부가 미확인. 허용이 없고 위탁이면 목적 외 이용 쟁점 | 제26조 제5항. 제15조 제1항 동의 목적 범위 |

수집·이용 동의로 광고 이벤트를 처리 중이었다면, 동의 시 알려야 할 사항은 목적, 항목, 보유·이용 기간, 거부권과 불이익이다. 철회 후에도 새 벤더가 같은 이벤트를 자기 최적화에 쓰면, 당초 목적 범위를 넘는지를 계약·실제 처리로 봐야 한다.

```text
제15조 ① 다음의 경우 수집할 수 있으며 그 수집 목적의 범위에서 이용할 수 있다.
  1. 정보주체의 동의를 받은 경우
  4. 정보주체와 체결한 계약을 이행하거나 체결 과정에서 요청에 따른 조치에 필요한 경우
② 동의를 받을 때 목적, 항목, 보유·이용 기간, 거부권 및 불이익을 알린다.
③ 당초 목적과 합리적으로 관련된 범위에서, 불이익·안전조치 등을 고려하여
   대통령령으로 정하는 바에 따라 동의 없이 이용할 수 있다.
```

**[제공된 법령 발췌] [VERIFIED]** — 제15조 제1항 제1호·제4호, 제2항, 제3항. 시행 2025-10-02. 직접 공식 사이트 확인 아님.

안내서가 인용한 시행령 제14조의2(추가 이용 기준 공개·CPO 점검)는 법령 발췌에 본문이 없다. 안내서 인용으로만 적고, 추가적 이용 근거를 광고 SDK 최적화에 바로 쓰지 않는다. 이번 사실관계도 추가적 이용 심사 기록이 아니다.

## 5. 벤더 계약·국외이전 — 확인 전에는 열지 말 것

안내서는 서비스형 LLM을 전제로, 저장·재이용(학습 포함)·국외이전을 계약으로 통제하고, 기업용 조건에서 입출력 미저장·학습 미활용·DPA를 권고한다. 광고 SDK에 그대로 적용되는 법정 서식이 아니다. 가져올 실무 포인트만 옮긴다.

- 벤더가 고객 목적 외에 자기 광고 최적화를 할 수 있는지
- 입력·이벤트 데이터의 소유·재이용 제한
- 파기 요청 시 처리
- 재위탁
- 서버 위치가 국외이면 국외이전 해당 여부

**[공식 실무자료] [VERIFIED: 안내서 권고 / 광고 SDK 의무 양식 아님]** — 안내서 PDF 27~28쪽.

국외이전이면 원칙 금지고, 동의, 계약 이행을 위한 위탁·보관으로서 처리방침 공개 또는 대통령령 방법 고지 등 예외를 갖춘 경우에만 가능하다. 이번 자료에 벤더 서버 위치는 없다.

```text
제28조의8 ① 국외 제공·처리위탁·보관은 원칙적으로 금지.
다만 별도의 동의, 법령·조약, 계약 이행을 위한 위탁·보관으로서
처리방침 공개 또는 대통령령 방법 고지 등 각 호에 해당하는 경우 가능.
⑤ 이 법을 위반하는 내용의 국외이전 계약을 체결하여서는 아니 된다.
```

**[제공된 법령 발췌] [VERIFIED]** — 제28조의8 제1항·제5항. 제2항 고지 항목은 발췌에 있으나, 이번 앱의 국외이전 해당 사실 자체는 [INSUFFICIENT].

안전조치는 내부관리계획, 접속기록 보관 등 대통령령에 따른 기술적·관리적·물리적 조치다. 세부 기준·고시는 이번 자료에 없다.

**[제공된 법령 발췌] [VERIFIED: 조문 존재]** — 제29조. 세부 기준 [INSUFFICIENT].

유출 통지·신고(제34조)는 SDK 교체 자체에 바로 적용하지 않는다. 철회 이후에도 식별 가능한 구매 이벤트가 광고 벤더로 계속 나간 사실이 나중에 확인되면, 그때 목적 외 제공·유출 해당 여부를 별도 검토한다. 지금은 전송 로그가 없어 유출로 단정하지 않는다.

## 6. 남은 확인

출시 전 아래가 닫히지 않으면, 철회가 서버·벤더까지 유효하다고 쓰지 않는다.

1. 구매 이벤트 항목: 광고식별자, 회원키, 이메일, 주문번호와 계정 결합 가능 여부.
2. 철회 전후 전송 로그: 신규 벤더로 실제 송신 여부, 시각, 이벤트 유형. 가능 상태만으로는 부족하다.
3. 벤더 suppression: 대상 식별자, 적용 목적(맞춤형 광고에 한정하는지), 적용 시각, 학습·최적화 복사본 포함 여부.
4. 계약: 위탁인지 제3자 제공인지, 목적 외 처리 금지, 독자 광고 최적화 허용 여부, 재위탁, 파기, 감사·로그 제공.
5. 수탁자 변경 고지: 광고·판매 권유 위탁이면 제26조 제3항 이행 여부. 처리방침 수탁자 공개(제26조 제2항)는 대통령령 방법이 발췌에 없어 세부 형식은 [INSUFFICIENT].
6. 국외 서버·국외 이전 해당 여부와, 해당 시 제28조의8 근거.
7. 기존 SDK 잔존 수집도구: 철회 후에도 구 벤더로 식별자가 남는지. 정책방안은 웹·앱 사업자가 제3자 수집도구를 처리방침에 웹·앱별로 공개하고, CPO가 수집도구 현황을 파악·점검할 것을 권고한다. 권고이지 법정 주기·필수 서식이 아니다.

**[공식 실무자료] [VERIFIED: 권고]** — 정책방안 PDF 29~30쪽. 제30조·제31조 본문 미제공.

제공되지 않아 판단하지 않는 것: 제17조, 제21조, 제22조, 제30조, 제31조, 제37조 본문, 시행령 세부, 과징금·과태료 액수, 안전성 확보조치 고시, 공식 서식.

## 7. 출시 전후 조치 (내부 실행용)

안내서·정책방안의 권고를 분기별 법정 점검이나 필수 양식으로 바꾸지 않는다. 이번 교체에 필요한 확인만 적는다.

### 출시 전

- 철회 테스트 계정의 서버 전송 로그를 확보한다. 화면·SDK 플래그만으로 완료 처리하지 않는다.
- 벤더에 식별자, 목적, 시각, 잔존 복사본(최적화·학습 포함)을 적은 suppression 확인을 받는다. “적용 완료” 한 줄은 기록으로 쓰지 않는다.
- 계약에서 독자 광고 최적화가 허용되는지 확인한다. 허용이면 동의 목적·위탁 범위와 맞는지 본다. 미확인 상태로 이벤트를 열지 않는다.
- 위탁·제3자 제공 분류를 정한다. 광고·판매 권유 위탁이면 수탁자 변경 고지문을 검토용으로만 작성하고, 게시·발송 전에 법무 확인을 받는다.
- 광고 경로와 성능 계측 경로를 분리한다. 집계 파이프라인에 광고식별자·회원키·매칭키를 넣지 않는다.
- 철회 이용자에게 새 광고 식별자를 다시 만들지 않는지, 구 SDK가 남아 있지 않은지 확인한다.

### 출시 직후

- 동일 테스트 계정으로 철회 후 N시간·N일 로그를 다시 본다. 점검 주기 숫자가 법령에 있는 것은 아니다. 교체 직후 실제 송신을 한 번 더 보는 작업이다.
- 벤더가 계약 목적 외 사용을 부인하는 회신과, 로그가 서로 맞는지 대조한다.
- 성능 계측은 식별자 없는 내부 집계 조건을 유지한다. 조건이 바뀌면 광고 철회와 다시 묶지 말고 별도 재분류한다.

### 이용자 화면

- “철회 완료”는 클라이언트 설정 변경을 넘는 의미를 주지 않는 편이 안전하다. 서버·벤더 확인 전에는 “맞춤형 광고 설정을 해제했습니다” 수준으로 두는 방안을 검토한다. 이 문안도 대외 게시 전 확인 대상이다.
