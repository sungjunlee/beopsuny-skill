# 출시 검토 메모 (초안) — 상담 티켓 외부 AI API 요약

**작성일:** 2026-09-08
**수신:** 제품팀
**건명:** 고객 상담 티켓의 외부 기업용 AI API 요약 기능 / 로컬 합성 데이터 데모 환경
**성격:** 내부 검토용 초안. 그대로 편집해 쓸 수 있게 작성했으나, 출시 승인·벤더 발송 전 법무 확정 필요.
**근거 범위:** 제공된 자료(개인정보 보호법 스냅샷 발췌, PIPC 생성형 AI 안내서 2025.8 발췌, PIPC 행태정보 정책방안 2024.1 발췌)에 한정. 공식 사이트를 지금 직접 조회한 것이 아니며, 미제공 조문·시행령·고시는 확인 불가로 표시했다.

---

## 1. 결론 요약

**현 상태로는 실제 고객 상담 데이터의 외부 API 송신 개시를 권고하지 않는다.** "학습 미사용" 계약 문구는 개인정보 검토 항목 중 **재이용(학습) 축 하나만** 해소한다. 보관, 국외이전, 위수탁 구조, 처리방침 공개는 별개 축이고, 이 중 국외이전은 근거 없이는 **금지**가 원칙이므로(제28조의8 제1항) 미확인 상태에서 송신을 시작하면 적법근거 미비 상태가 된다.

미제공 별첨(보관 설정 / 안전성 모니터링 / 지원 인력 접근 국가) 3건은 단순 참고자료가 아니라 **적법근거를 구성하는 데 필요한 사실**이다. 이 3건 없이는 처리방침에 공개할 국외이전 고지사항(제28조의8 제2항 각 호)을 작성할 수조차 없다. → **출시 차단 항목(blocker)**.

**데모 환경은 별개다.** 제시된 사실(합성 문장, 실제 고객과 미연결, 로컬 모델, 외부 송신·원격 접근·로그 없음)이 맞다면 개인정보 처리 자체가 없으므로 제26조·제28조의8 의무가 발생하지 않는다. 외부 API와 동일한 벤더·국외이전 확인 절차를 **반드시 거칠 필요는 없다.** 대신 경량 게이트 2개(합성 데이터 진위, 환경 격리 유지)로 대체할 것을 권고한다.

## 3. 항목별 검토

### 3.1 개인정보 해당성 — 마스킹만으로 벗어나지 않는다 (지금 판단 가능)

이름·전화번호를 가려도 **주문 식별자**가 남는다. 주문 식별자는 회사 내부 주문·회원 정보와 직접 연결되므로, 회사 관점에서 결합이 용이하다. 자유기재 본문에도 주소·성함·계정 등 식별정보가 잔존할 가능성이 높다(U8).

- PIPC 행태정보 정책방안은 온라인 식별자를 랜덤 생성했더라도 "누적·중첩·결합으로 특정 개인을 식별할 가능성이 발생한 경우"에는 개인정보에 해당할 가능성이 높다고 본다. 식별성이 없다고 보려면 **개인정보와 결합될 매칭키가 없어야 한다**고 서술한다. **[공식 실무자료] [VERIFIED — 번들 범위]** — PDF 22·25쪽. 단, 이 문서는 맞춤형 광고 행태정보 맥락이므로 본 건에 직접 적용되는 규범이 아니라 **식별성 판단 프레임 참고**로만 사용했다.
- 개인정보 정의 조문(제2조 제1호) 원문은 번들에 없다 → **[INSUFFICIENT]**. 조문 대조가 필요하면 법무에서 별도 확인.

**판단:** 본 건은 개인정보 처리로 전제하고 검토한다. "마스킹했으니 개인정보가 아니다"는 근거가 되지 않는다.

### 3.2 "학습 미사용" 문구의 범위 — 개발팀 판단은 성립하지 않는다 (지금 판단 가능)

PIPC 생성형 AI 안내서는 서비스형 LLM 이용 기업이 **사전에 검토할 항목을 두 개로 병렬 제시**한다: ①이용자 데이터의 **보관 및 재이용(AI 학습 포함)** 여부, ②**국외이전** 여부. **[공식 실무자료] [VERIFIED — 번들 범위]** — PDF 27쪽.

즉 "학습 미사용"은 ①의 일부만 답한 것이고, **보관 여부와 ②는 미해결**이다. 안내서는 기업용 API가 "기본적으로 입출력값 미저장, 학습 미활용(기본값)"이라고 비교표에 적고 있으나, 자료 자체가 **2025.8 기준 벤더 상품 스냅샷(OpenAI 중심)**이며 현재 벤더 사실을 확정하지 않는다고 명시한다. 우리 벤더의 실제 보관 설정은 별첨(U3)으로만 확인 가능하다.

특히 **안전성 모니터링(U4)은 통상 저장·인적 검토를 수반**할 수 있는 기능이다. "학습에 안 쓴다"와 "저장하지 않는다"는 다른 문장이므로, 계약 문구만으로 보관 축을 종료할 수 없다.

**판단:** 개인정보 검토 종료 주장은 성립하지 않는다. 최소 U1~U6 확인 후 재판단.

### 3.3 위탁 vs 제3자 제공 (제26조)

외부 API 송신은 우리 목적을 위해 벤더가 처리하는 구조이므로 **처리위탁으로 보는 것이 출발점**이다. 안내서의 DPA 비교표도 "고객=처리자 / 벤더=수탁자 명시"를 기업용 계약의 통상 구성으로 적는다(PDF 28쪽, 벤더 스냅샷).

**단, 분기 조건이 남아 있다.** 벤더의 안전성 모니터링이 벤더 **자기 목적** 처리로 설계돼 있으면 그 부분은 위탁 범위를 벗어나 제3자 제공 검토가 필요해지고, 별도 동의 축이 새로 생긴다. → U4가 이 분기를 결정한다.

위탁으로 확정될 경우 발생하는 **법정 의무** (근거: 개인정보 보호법 스냅샷 발췌, **[공식 원문 기반 스냅샷 발췌] [VERIFIED — 번들 범위]**):

| 조항 | 의무 | 현 상태 |
|---|---|---|
| 제26조 제1항 | 위탁업무 목적 외 처리 금지 / 기술적·관리적 보호조치 / 대통령령 사항을 **포함한 문서**로 체결 | 문서화 여부 미확인 (U5) — 시행령 사항은 원문 미제공 **[INSUFFICIENT]** |
| 제26조 제2항 | 위탁 업무 내용과 수탁자를 정보주체가 쉽게 확인하도록 **공개** | 처리방침 반영 미확인 (U7) |
| 제26조 제4항 | 수탁자 **교육 및 처리 현황 점검 등 감독** | 체계 미확인 |
| 제26조 제6항 | 수탁자의 **재위탁 시 위탁자 동의** | 서브프로세서 구조 미확인 (U6) |
| 제26조 제8항 | 수탁자에 제15조·제28조의8·제29조·제34조 등 준용 | 사고 통지 경로를 계약에 명시할 것 |

※ 제26조 제3항(정보주체 통지)은 **홍보·판매권유 업무 위탁**에 적용되므로 본 건에는 해당하지 않는다.
※ 처리방침 조문(제30조) 원문과 "대통령령으로 정하는 방법" 세부는 번들 미제공 → 공개 방식의 구체 요건은 **[INSUFFICIENT]**.

### 3.4 국외이전 (제28조의8) — 최대 리스크

**구조:** 제1항은 국외 **제공(조회되는 경우를 포함)·처리위탁·보관을 원칙적으로 금지**하고, 각 호의 근거가 있을 때만 허용한다. **[공식 원문 기반 스냅샷 발췌] [VERIFIED — 번들 범위]**

여기서 두 가지가 결정적이다.

1. **"조회 포함"** — 저장이 국내라도, **해외 지원 인력이 원격 조회하면 국외이전**이다(U2). 안전성 모니터링을 해외 팀이 수행해도 마찬가지다.
2. **입증 방향** — 근거를 갖춘 뒤 이전하는 구조다. "국외이전이 아니라는 증거가 없으니 진행"은 반대 방향이다.

**근거 경로별 검토:**

| 경로 | 요건 | 본 건 적용 |
|---|---|---|
| 제1항 1호 | 정보주체 **별도 동의** + 제2항 5개 항목 사전 고지(이전 항목 / 국가·시기·방법 / 이전받는 자 명칭·연락처 / 이용목적·보유이용기간 / 거부 방법·절차·효과) | 별첨 없이는 5개 항목을 채울 수 없음. 제3항상 항목 변경 시 재고지·재동의 필요 → 서브프로세서 변경 잦으면 운영 부담 큼 |
| 제1항 3호 | **정보주체와의 계약 체결·이행에 처리위탁·보관이 필요**한 경우로서, 가목(제2항 각 호를 처리방침에 공개) 또는 나목(전자우편 등으로 통지) | 실무상 유력 경로. 다만 **"필요성" 요건이 쟁점**: 상담 처리 자체는 계약 이행이지만, AI 요약이 그 이행에 필요한지 vs 내부 효율화인지는 논거 문서화 필요 |
| 제1항 4호 / 5호 | 인증 취득 + 조치 / 보호위 적정성 인정 | 해당 여부 미확인 **[INSUFFICIENT]** |

**경고 사례:** 안내서는 통화 녹음·요약 서비스에서 개인정보가 국외 서버로 이전되었으나 **국외이전 고지사항이 처리방침에서 일부 누락되어 제28조의8 제1항 제3호 적법근거를 갖추지 못한** 사례(제2024-010-184호 결정)를 싣고 있다. **[공식 실무자료] [VERIFIED — 번들 범위]** — PDF 28쪽. 요약 서비스·국외이전·처리방침 공개라는 본 건과 구조가 거의 같고, **실패 지점이 "공개의 완전성"**이었다는 점을 유의할 것.

**추가:** 제28조의8 제5항은 **이 법을 위반하는 내용의 국외이전 계약 체결을 금지**한다 → 계약·DPA 검토 시 확인 항목.

**판단:** U1·U2가 확정되기 전까지 실 고객 데이터 송신 개시 보류. 3호 경로를 택할 경우, 별첨 수령 → 제2항 5개 항목 확정 → 처리방침 개정 게시가 **송신 개시보다 먼저** 완료돼야 한다.

### 3.5 QA 다운로드와 평가 버튼 기록

요약 결과는 상담 본문에서 파생된 개인정보일 수 있으므로, QA팀 다운로드는 **별도 처리 축**이다.

- **목적 범위:** 상담 품질관리가 원 수집 목적 범위 내인지(제15조 제1항), 아니면 **추가적 이용**(제15조 제3항)인지 확인 필요(U7). 안내서가 인용한 **시행령 제14조의2 제2항**은 추가적 이용이 **지속적으로 발생하는 경우 판단 기준을 처리방침에 공개하고 CPO가 점검**할 것을 요구한다 (PDF 20쪽, 안내서 내 인용 — 시행령 원문 자체는 미제공 **[UNVERIFIED — 원문 미대조]**).
- **안전조치(제29조):** 다운로드 파일의 저장 위치·접근권한·접속기록·보관기간·파기를 별도 통제. 세부 기준은 대통령령 위임이고 시행령·고시 미제공 → **[INSUFFICIENT]**.
- **평가 버튼 기록:** 현재 자체 학습 활용 사실은 **확인되지 않았다**(F7). 따라서 학습을 전제로 판단하지 않는다. 다만 **향후 이 로그로 미세조정·자체 학습을 하려면 법적 근거·전처리를 별도 검토**해야 한다(안내서 PDF 50쪽 모델이용자 항목: 법적근거 검토, 추가학습 데이터 전처리). 이는 조건부 항목이며 현재 출시 차단 사유는 아니다.

### 3.6 안전조치·사고 대응

- 제29조: 내부 관리계획 수립, 접속기록 보관 등 (대통령령 위임, 세부 미확인).
- 제34조: 유출등 인지 시 정보주체 통지 5개 항목 + 보호위 신고. **제26조 제8항에 따라 수탁자에게도 준용**되므로, 벤더 사고 시 통지 자료 제공·공조 의무를 **계약에 명시**할 것을 권고.
- 신고 기준·기한 등 세부는 대통령령 위임이고 시행령 미제공 → **[INSUFFICIENT]**. 별도 확인 필요.
- **시행일 유의:** 번들의 법령 스냅샷은 **시행 2025-10-02, 법률 제20897호** 기준이며, "2026-09-11 예정법을 현재법으로 적용하지 않는다"고 명시한다. 출시 시점이 2026-09-11 이후라면 개정 내용 확인이 필요한데, 해당 조문 원문이 번들에 없어 **내용·적용 범위 확인 불가** **[INSUFFICIENT]**. 법무에서 현행 원문 재확인 필요.

## 4. 데모 환경 — 동일 절차 강제는 불필요

**질문에 대한 답: 아니오. 제시된 사실 전제 하에서는 외부 API와 동일한 벤더·국외이전 확인 절차를 반드시 거칠 필요가 없다.**

**근거:**
- 제26조와 제28조의8은 **개인정보**를 대상으로 한다. 합성 문장이 실제 고객과 연결되지 않고 결합 매칭키가 없다면 개인정보 처리가 아니므로 두 조항의 의무가 발생하지 않는다.
- 제28조의8 제1항의 구성요건은 제공(조회 포함)·처리위탁·보관이다. 외부 송신·원격 접근·로그가 없다면 **구성요건 자체가 성립하지 않는다.**
- 벤더가 없으므로 위수탁 관계도 성립하지 않는다.

**다만 이 결론은 아래 조건에 달려 있다. 조건이 깨지면 결론도 바뀐다.**

| 조건 | 확인 방법 |
|---|---|
| C1. 합성 문장이 **실제 상담 본문에서 파생·변형된 것이 아닐 것** | 생성 방식·출처 문서화. 실데이터 파생이면 누적·중첩·결합에 의한 재식별 가능성 검토 필요 |
| C2. 실제 고객과 연결할 **매칭키가 없을 것** (주문번호·회원ID·해시 포함) | 데이터셋 스키마 점검 |
| C3. 로컬 모델·컨테이너가 **외부 호출을 하지 않을 것** | 제공된 테스트의 수행일·범위·수행자 확인, 네트워크 격리 설정 증적 |
| C4. 환경이 그대로 **유지될 것** | 실데이터 투입·외부 송신·원격 접근 추가 시 즉시 재검토 게이트 발동 |

**법정 의무와 실무 권고 구분:**

- **법정 의무:** 위 조건이 유지되는 한 **없음**(제공된 사실 기준).
- **실무 권고(법정 의무 아님):** ①테스트 결과의 일자·범위·수행자 기록 보관, ②네트워크 차단·환경 분리 설정 증적 보관, ③데모→운영 승격 시 CPO 점검 게이트, ④로컬 모델의 라이선스·모델카드 확인. ③④는 안내서 PDF 50쪽 모델이용자 항목에 근거하나, **해당 표는 원본에서 색상으로 법적 의무/자율 이행을 구분하며 텍스트 추출에서 색이 보존되지 않았다**(출처 자료 자체의 명시). 따라서 이 표만으로 개별 항목을 법적 의무로 취급하지 않고 **권고 후보**로 분류했다.

**권고 처리:** 데모는 경량 게이트(C1·C2 문서 확인 + C3 테스트 증적 보관)로 통과시키고, **C4 위반 시 자동으로 외부 API와 동일한 검토 트랙으로 이관**되도록 조건을 명시할 것.

## 5. 벤더 별첨 요청 항목 (초안 — 발송 전 법무 확인 필요)

아래는 그대로 편집해 쓸 수 있는 요청 목록이다. 실제 발송은 법무 확인 후 담당 부서에서 진행할 것.

1. **데이터 보관:** 입력·출력값 저장 여부, 저장 시 보관기간, 저장 위치(국가·리전), 백업 위치·기간, 삭제 요청 시 파기 절차와 소요 기간
2. **안전성 모니터링:** 목적, 수행 주체(벤더 자기 목적 여부 명시), 인적 검토 포함 여부, 대상 데이터 범위, 별도 보관기간, 접근 권한자
3. **지원 인력 접근:** 접근 가능 국가, 접근 조건(티켓 기반 여부), 접근 범위, 접근 로그 제공 여부
4. **계약 구조:** DPA 유무, **위수탁 관계 명시 조항**(고객=처리자 / 벤더=수탁자), 입력 데이터 소유권, 재이용 제한, 안전조치(전송·저장 암호화·접근통제·로그관리), 데이터 파기
5. **재위탁:** 서브프로세서 전체 목록, 각 소재 국가, 변경 시 사전 통보·이의제기 절차
6. **국외이전 고지자료:** 이전 항목 / 이전 국가·시기·방법 / 이전받는 자 명칭·연락처 / 이용목적·보유이용기간 — 처리방침 공개용 확정 문구 작성에 필요
7. **사고 대응:** 유출 인지 시 통지 기한·경로, 통지 항목, 증적 제공 범위, 공조 담당자
8. **감사·권리행사:** 감사 로그·접근 기록 제공 방식, 정보주체 열람·삭제·처리정지 요청의 벤더 전파 경로와 회신 서식

※ 4~7의 항목 구성은 안내서 PDF 28쪽의 기업용 이용약관·DPA 비교표를 **점검 항목 후보**로 활용했다. 해당 표는 2025.8 기준 벤더 스냅샷이며 우리 벤더의 사실을 확정하지 않는다.

## 8. 이 메모가 확정하지 않은 것

- 본 건이 국외이전에 해당하는지 — 별첨 미수령으로 **판단 불가**. "해당하지 않는다"고 결론 내리지 않았다.
- 위탁인지 제3자 제공인지 — 안전성 모니터링 성격 미확인으로 **분기 미확정**.
- 개인정보 보호법 시행령·고시상 세부 기준(안전조치 항목, 유출 신고 기준·기한, 처리방침 공개 방법) — 원문 미제공으로 **확인 불가**.
- 2026-09-11 시행 예정 개정 내용 — 원문 미제공으로 **확인 불가**.
- 벤더의 실제 보관·학습·접근 정책 — 계약 문구 외에는 확인된 것이 없다. 안내서의 벤더 비교표는 2025.8 스냅샷이며 우리 벤더 사실이 아니다.
- 회사의 별도 학습 수행 여부 — 확인되지 않았고, 수행한다고 전제하지 않았다.
- 본 메모는 확인한 인용 범위의 검토 결과이며, 최종 적법성 보증이 아니다. 출시 승인 및 대외 문서(처리방침 개정문, 벤더 발송문) 확정은 법무 검토를 거칠 것.
