# 제품팀 전달용 출시 검토 메모(초안)

**검토 기준일:** 2026년 9월 8일  
**검토 범위:** 제공된 사실과 고정 출처 발췌에 한정  
**결론:** 실고객 데이터를 사용하는 외부 AI API 기능은 **조건부 출시 보류**가 타당합니다. 반면, 제시된 격리 조건이 유지되는 합성데이터 로컬 데모는 동일한 개인정보 위탁·국외이전 심사를 반드시 거칠 필요가 없습니다.

## 1. 요약 결론

외부 API 계약의 “고객 콘텐츠를 모델 학습에 사용하지 않는다”는 문구만으로 개인정보 검토가 끝났다고 볼 수 없습니다. 이 문구는 재이용 목적 중 하나인 모델 학습을 제한할 뿐, 다음 사항을 확인해 주지 않습니다.

- 입력·출력 데이터의 저장 여부와 보관기간
- 안전성 모니터링 과정에서의 열람·재이용 여부
- 벤더 및 지원 인력의 접근 권한과 접근 국가
- 재수탁자와 재위탁 절차
- 계약 종료·삭제 요청 시 파기
- 보안조치, 사고 통지, 감사·감독 수단
- 국외이전 발생 여부와 적법근거

따라서 별첨 또는 DPA를 확보하고 아래 출시 전 필수 확인사항을 해소하기 전에는 실고객 티켓을 전송하지 않는 것이 적절합니다.

## 2. 현재 확인된 사실

다음은 법률 판단이 아니라 제공된 제품 사실입니다.

- 송신 전 고객 이름과 전화번호를 가립니다.
- 자유기재 상담 본문과 주문 식별자는 외부 API로 전송됩니다.
- 계약에는 고객 콘텐츠를 모델 학습에 사용하지 않는다는 문구가 있습니다.
- 요약 결과는 상담원 화면에 표시됩니다.
- 내부 QA팀은 일부 요약 결과와 평가 버튼 기록을 내려받을 수 있습니다.
- API의 보관 설정, 안전성 모니터링, 지원 인력 접근 국가에 관한 별첨은 제공되지 않았습니다.
- 회사가 별도 모델 학습을 수행한다는 사실은 확인되지 않았습니다.
- 별도 데모는 실존 고객과 연결할 수 없는 합성 문장만 사용하며, 로컬 모델 처리·외부 송신 없음·원격 접근 없음·로그 없음이라는 테스트 결과가 제공됐습니다.

## 3. 지금 판단할 수 있는 사항

### 3.1 이름과 전화번호를 가린 것만으로 개인정보가 아니라고 단정할 수 없음

자유기재 본문에는 고객이 직접 입력한 이름, 주소, 결제·배송 정보, 민감한 상담 내용 등이 남을 수 있습니다. 주문 식별자 역시 회사가 보유한 주문·회원 정보와 연결할 수 있다면 특정 고객과 결합될 가능성이 있습니다.

제공된 정책자료도 랜덤 식별자라 하더라도 다른 정보와 결합하거나 누적 처리하여 개인을 식별할 수 있으면 개인정보가 될 가능성이 높다고 설명합니다. 다만 해당 자료는 온라인 행태정보에 관한 정책자료이므로, 이번 주문 식별자의 법적 성격을 직접 확정하는 근거라기보다 식별 가능성 판단을 위한 참고 기준입니다.

따라서 현재 단계에서는 외부 송신 데이터를 **개인정보일 가능성이 높은 데이터로 취급**해야 합니다. 실제로 개인정보에 해당하지 않는다고 보려면 본문 필터링 범위, 주문 식별자의 구조, 벤더가 보유한 결합 가능 정보 등을 추가 확인해야 합니다.

**근거:** [공식 실무자료 발췌] `[UNVERIFIED]` — 「맞춤형 광고에 활용되는 온라인 행태정보 보호를 위한 정책 방안」 22쪽. 사용자 제공 고정 PDF 발췌만 확인했으며 공식 사이트 원문과 2026년 9월 8일 현재성을 직접 대조하지 않음.

### 3.2 “학습 미사용”은 개인정보 처리 전체를 배제하지 않음

외부 API는 입력을 받아 요약 결과를 생성하므로, 학습하지 않더라도 입력 데이터의 전송·열람·일시 저장·안전성 모니터링·출력 생성 과정이 남을 수 있습니다.

개인정보위 안내서도 서비스형 LLM 이용 시 데이터의 보관·재이용·학습 여부와 국외이전 여부를 별도로 검토하고, 이용약관 및 DPA에서 입력데이터 소유권, 재이용 제한, 안전조치, 파기 등을 명확히 규정할 것을 권고합니다.

따라서 개발팀의 “학습에 사용하지 않으므로 개인정보 검토가 끝났다”는 결론은 현재 자료만으로는 받아들이기 어렵습니다.

**근거:** [공식 실무자료 발췌] `[UNVERIFIED]` — 「생성형 인공지능(AI) 개발·활용을 위한 개인정보 처리 안내서」 27~28쪽. 사용자 제공 고정 PDF 발췌 확인; 현행 법령 전체와 현재 벤더 상품 조건은 미확인.

### 3.3 외부 API 처리는 개인정보 처리위탁으로 검토할 필요가 큼

현재 설명대로라면 회사의 고객상담 업무를 위해 외부 사업자가 데이터를 받아 요약하는 구조이므로, 우선 개인정보 처리위탁 구조로 검토하는 것이 합리적입니다. 다만 벤더가 안전성 모니터링 등의 자체 목적으로 데이터를 사용하는 경우에는 그 범위가 순수한 수탁처리를 벗어나는지 별도 검토해야 합니다.

제공된 개인정보 보호법 제26조 발췌에 따르면 개인정보 처리업무 위탁 시에는 문서에 다음 내용을 포함해야 합니다.

- 위탁 목적 외 처리 금지
- 기술적·관리적 보호조치
- 대통령령에서 정한 그 밖의 안전관리 사항

또한 위탁업무와 수탁자 공개, 수탁자 교육·감독, 재위탁 시 위탁자 동의가 요구됩니다. 현재 확인된 “학습 미사용” 문구 하나만으로 이러한 항목이 모두 충족됐다고 판단할 수 없습니다.

**근거:** [공식 원문 기반 법령 스냅샷] `[UNVERIFIED]` — 개인정보 보호법 제26조 제1·2·4·5·6항. 사용자 제공 스냅샷 확인(시행일 2025-10-02); 2026년 9월 8일 현재 법령을 공식 사이트에서 직접 확인하지 못함.

### 3.4 해외 서버 또는 해외 인력의 조회가 있으면 국외이전 검토 대상이 될 수 있음

제공된 제28조의8 발췌는 국외에서의 제공뿐 아니라 처리위탁·보관 및 “조회되는 경우”도 국외이전에 포함합니다. 따라서 다음 중 하나라도 있으면 국외이전 검토가 필요합니다.

- 입력·출력이 해외 리전에 저장 또는 처리됨
- 해외 지원·보안 인력이 고객 데이터를 조회할 수 있음
- 해외 재수탁자가 모니터링·운영에 관여함
- 장애 분석이나 사고 대응을 위해 해외에서 로그를 열람함

국외이전 근거로 정보주체와의 계약 이행 필요성을 사용하려면, 해당 위탁·보관이 계약 체결·이행에 필요한지와 법정 고지사항이 처리방침 또는 정해진 방법으로 제공됐는지를 확인해야 합니다. 고객상담 요약의 편의성만으로 그 필요성을 자동 인정할 수는 없습니다.

**근거:** [공식 원문 기반 법령 스냅샷] `[UNVERIFIED]` — 개인정보 보호법 제28조의8 제1항·제2항·제4항. 사용자 제공 스냅샷 확인; 현행 시행령상 세부 절차·보호조치 및 2026년 9월 8일 현재성은 미확인.

### 3.5 QA 다운로드도 별도 통제 대상

내부 QA팀의 열람 자체를 외부 제공이라고 단정할 근거는 없습니다. 다만 요약 결과와 평가 기록이 주문 식별자 또는 상담 본문과 연결되면 개인정보 사본이 추가로 생성되고 접근 범위가 확대될 수 있습니다.

개인정보 보호법 제29조 발췌상 개인정보처리자는 기술적·관리적·물리적 안전조치를 해야 합니다. 이에 따라 QA 다운로드의 권한, 보관 위치, 재전송 가능성, 보관기간, 삭제 절차, 접근기록을 정해야 합니다.

**근거:** [공식 원문 기반 법령 스냅샷] `[UNVERIFIED]` — 개인정보 보호법 제29조. 사용자 제공 스냅샷 확인; 구체적인 현행 안전조치 기준 고시는 제공되지 않음.

## 4. 출시 전 필수 확인사항

다음 항목이 해소되기 전에는 실고객 데이터 전송을 보류하는 것을 권고합니다.

| 구분 | 확인할 사항 | 판단 기준 |
|---|---|---|
| 데이터 범위 | 자유기재 본문에 남는 개인정보 유형, 주문 식별자의 고객 재연결 가능성 | 이름·전화번호 마스킹만으로 충분한지 재평가 |
| 처리 목적·근거 | 기존 고객상담 목적과 AI 요약의 관계, 고객 고지·처리방침 내용 | 제15조 제1항의 근거 또는 제3항 추가 이용 기준 충족 여부 |
| 계약/DPA | 목적 외 이용 금지, 안전조치, 보관·삭제, 재수탁, 사고 통지, 감사·감독 | 제26조 요건을 계약 문서에서 확인 |
| 저장 | 입력·출력·로그의 저장 여부, 보관기간, 삭제 방식, 백업 잔존 | “학습 미사용”과 별도로 확인 |
| 모니터링 | 안전성·오남용 모니터링 시 사람의 열람 여부와 이용 목적 | 수탁 범위 및 목적 외 이용 여부 판단 |
| 국가 | 처리 리전, 백업 국가, 지원 인력·재수탁자 접근 국가 | 국외이전 발생 여부 판단 |
| 국외이전 근거 | 동의, 계약 이행상 필요한 위탁·보관, 인증 등 적용 근거 | 제28조의8 요건과 고지사항 확인 |
| QA 운영 | 다운로드 대상, 주문번호 포함 여부, 권한, 저장 위치, 보관·삭제 | 최소 접근과 안전조치 설계 |
| 사고 대응 | 벤더의 사고 통지 기한과 협조 의무 | 법 제34조 대응이 가능하도록 계약·절차 마련 |

제15조 제3항의 “당초 목적과 합리적으로 관련된 추가 이용”을 고려한다면 정보주체의 불이익, 예측 가능성, 안전조치 및 시행령상 세부 기준을 함께 평가해야 합니다. 제공 자료에는 기존 처리방침과 고객 고지, 당초 수집 목적이 없으므로 현재는 적용 여부를 확정할 수 없습니다.

**근거:** [공식 원문 기반 법령 스냅샷] `[UNVERIFIED]` — 개인정보 보호법 제15조 제1·3항 및 안내서 20쪽의 시행령 제14조의2 발췌. 기존 고지 내용과 현행 하위규정 전체가 없어 결론 유보.

## 5. 법정 의무와 실무상 권고 구분

### 법정 의무로 검토할 사항

- 개인정보 처리의 적법근거 마련: 법 제15조
- 처리위탁 문서화, 수탁자 공개·감독 및 재위탁 동의: 법 제26조
- 필요한 기술적·관리적·물리적 안전조치: 법 제29조
- 국외 조회·위탁·보관이 있으면 국외이전 적법근거와 관련 의무 검토: 법 제28조의8
- 유출 발생 시 통지·신고 및 피해 최소화 조치: 법 제34조

단, 시행령상 세부 요건과 2026년 9월 8일 현재 조문은 고정 출처에 완전하게 제공되지 않았으므로 출시 승인 전에 현행 공식 원문 확인이 필요합니다.

### 실무상 권고

- 자유기재 본문에도 개인정보 탐지·삭제 또는 치환 필터 적용
- 외부 API에 불필요한 주문 식별자를 보내지 않거나 일회성 토큰으로 대체
- 입력·출력 무보관 설정을 기술 설정과 계약 양쪽에서 확보
- 사람의 모니터링 접근을 예외적 상황으로 제한하고 접근기록 확보
- QA 다운로드 대신 권한이 통제되는 검토 화면을 우선 사용
- 다운로드가 필요하면 표본 최소화, 로컬 재식별키 제거, 자동 만료 적용
- 출시 전 실제 페이로드·로그·장애 대응 경로를 포함한 개인정보 흐름도 작성

안내서 50쪽 체크리스트는 색상 정보가 추출 과정에서 사라졌으므로, 그 페이지의 개별 항목을 모두 법정 의무라고 취급하지 않았습니다.

## 6. 합성데이터 로컬 데모

제공된 사실이 그대로 유지된다면 다음과 같이 판단할 수 있습니다.

- 실존 고객과 연결할 수 없는 합성 문장만 처리
- 외부 송신 없음
- 원격 접근 없음
- 로그 없음

이 조건에서는 외부 벤더가 고객 개인정보를 처리하거나 국외에서 조회·보관한다는 사실이 없습니다. 따라서 **실고객 외부 API 기능과 동일한 개인정보 위탁·국외이전 확인 절차를 데모에 그대로 적용해야 한다고 볼 근거는 제공 자료에 없습니다.**

데모는 별도로 진행할 수 있다는 판단입니다. 다만 이는 다음 조건부입니다.

- 실고객 티켓을 복사하거나 변형한 문장을 합성데이터로 사용하지 않을 것
- 주문번호 등 운영 식별자를 넣지 않을 것
- 모델·SDK의 텔레메트리, 오류보고, 자동 업데이트 과정에서 외부 송신이 발생하지 않을 것
- 원격 지원이나 클라우드 백업을 활성화하지 않을 것
- 향후 외부 API 연결 시점에는 본 메모의 출시 gate를 다시 적용할 것

동일 벤더 제품이라는 이유만으로 국외이전이 발생하는 것은 아닙니다. 실제 데이터의 국외 제공·조회·처리위탁·보관이 있는지가 기준입니다. 다만 라이선스, 공급망 보안 등 비개인정보 영역의 벤더 검토는 별도로 할 수 있습니다.

## 7. 제품팀 전달 문안

> 외부 기업용 AI API의 학습 미사용 조항은 긍정적이지만, 이것만으로 개인정보 검토가 완료되지는 않습니다. 자유기재 상담 본문과 주문 식별자는 고객과 연결될 가능성이 있어 개인정보로 취급하여 설계해야 합니다.  
>   
> 실고객 출시 전까지 DPA 및 보관·모니터링·재수탁·지원 인력 접근 국가 자료를 확보하고, 위탁 공개·감독, 안전조치, 국외이전 발생 여부와 적법근거, QA 다운로드 통제를 확인해 주세요. 이 사항이 해소될 때까지 실고객 데이터의 외부 전송은 보류합니다.  
>   
> 실존 고객과 연결할 수 없는 합성데이터만 로컬에서 처리하고 외부 송신·원격 접근·로그가 없는 데모는 별도로 진행할 수 있습니다. 다만 텔레메트리와 오류보고를 포함한 외부 통신 부재가 계속 유지되어야 하며, 실제 고객 데이터 또는 외부 API를 연결하는 시점에는 정식 개인정보 검토를 다시 받아야 합니다.
