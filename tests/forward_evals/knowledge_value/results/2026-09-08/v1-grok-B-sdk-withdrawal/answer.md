# SDK 교체 검토 메모 (초안)

- **일자:** 2026-09-08  
- **대상:** 앱팀, 개인정보 담당  
- **사안:** 커머스 앱 광고 SDK 교체 — 맞춤형 광고 철회가 화면·신규 SDK 설정 밖으로도 막히는지, 성능 계측과 어떻게 나눌지  
- **적용 시점:** 제공된 개인정보 보호법 발췌(법률 제20897호, 시행 2025-10-02)를 현재법 후보로 본다. 2026-09-11 예정법은 쓰지 않는다.  
- **확인 한계:** 아래 법령·안내 인용은 **제공된 캡처 텍스트 번들**만 대조했다. 공식 사이트를 연 확인이 아니며, 미제공 조문·시행령·고시 전문은 확인하지 못했다.

---

## 1. 지금 증거로 말할 수 있는 것

화면 철회와 신규 SDK 광고 설정 OFF는 **클라이언트 경로의 철회 신호**로는 볼 수 있다. 그 사실만으로 광고 목적 처리가 서버·벤더까지 멈췄다고 볼 수는 없다.

| 경로 | 이번 점검에서 확인된 사실 | 판단 |
| --- | --- | --- |
| 앱 화면 | 맞춤형 광고 OFF 시 “철회 완료” 표시 | 이용자 접점 신호는 있음 |
| 신규 SDK 설정 | 광고 설정도 꺼짐 | 클라이언트 SDK 설정과 화면은 맞춰 둔 상태 |
| 서버 이벤트 수신기 | 구매 이벤트를 새 벤더로 **보낼 수 있음**. 실제 전송 로그는 없음 | 서버 경유 가능. 전송 여부·차단 여부는 미확인 |
| 벤더 회신 | “suppression 적용 완료”만 있음. 대상 식별자·목적·적용 시각 없음 | 적용 범위·시점을 재조회할 수 없음 |
| 계약 | 벤더 독자 광고 최적화 허용 여부 미확인 | 위탁 목적 외 이용인지 제3자 자기 목적인지 못 가림 |
| 성능 계측 | 개인·기기 식별자 없음, 재식별 불가 집계, 내부만 처리, 외부 전송 없음 | 광고 철회와 별 축. 아래 3절 |

제품팀 주장(“화면과 회신만으로 충분”)은 이번 증거로는 받아들이기 어렵다. 다른 담당 주장(“모든 이벤트·모든 보존 데이터를 즉시 삭제”)도 이번 번들만으로는 법정 결론으로 세울 수 없다. 광고 목적 처리와 내부 집계 계측을 한 묶음으로 지우라는 말은, 확인된 사실과도 어긋난다.

## 2. 광고 SDK 쪽에 붙는 법령·정책 축

광고 SDK·구매 이벤트는 식별자나 회원정보와 붙을 가능성이 큰 행태 처리다. 페이로드를 아직 못 봤으므로 **개인정보 해당을 단정하지는 않는다.** 다만 식별 처리로 보면 동의·목적 범위가 먼저이고, 식별하지 않는 처리로 보려면 결합 금지가 먼저다.

**수집·이용 근거**  
개인정보 보호법 제15조제1항은 동의 등 각 호 중 하나에 해당할 때만 수집하고, 그 목적 범위에서 이용할 수 있다고 한다. 같은 조 제2항은 동의 시 목적·항목·보유기간·거부권과 불이익을 알리도록 한다.  
**[공식 원문 스냅샷] [UNVERIFIED]** — 제공된 법령 발췌 제15조. 직접 공식 사이트 확인 아님.

맞춤형 광고 정책 방안은, 식별하여 처리하면 수집·이용을 알리고 동의를 받으며 선택 동의 거부를 이유로 서비스 제공을 거절하지 말라고 하고(법 제15조, 제22조 인용), 처리방침·환경설정 등으로 사후 거부 기능을 두라고 한다(법 제37조 인용). 제22조·제37조 본문은 이번 법령 발췌에 없다. 정책이 그 조를 인용한다는 점만 적고, 조문 내용은 추정하지 않는다.  
**[공식 실무자료] [UNVERIFIED]** — 「맞춤형 광고에 활용되는 온라인 행태정보 보호를 위한 정책 방안」(2024.1) PDF 25쪽 대응 발췌(문서 −21쪽).

**위탁·목적 외 이용**  
제26조제1항은 처리 업무 위탁을 문서로 하고, 위탁 목적 외 처리 금지와 보호조치를 넣도록 한다. 제26조제4항은 수탁자 교육·처리 현황 점검 등 감독을, 제26조제5항은 수탁자의 위탁 범위 초과 이용·제3자 제공 금지를 둔다. 제26조제2항은 위탁 업무와 수탁자를 공개하도록 한다. 홍보·판매 권유 위탁이면 제26조제3항에 따라 내용·수탁자 변경도 알려야 한다.  
벤더가 우리 광고 집행만 하는지, 자기 광고 최적화를 하는지는 계약이 비어 있어 **위탁인지 자기 목적 이용인지부터 미확정**이다. 자기 목적이면 제26조 위탁 문서만으로 덮이지 않을 수 있다. 제17조(제3자 제공) 본문은 이번 발췌에 없다.  
**[공식 원문 스냅샷] [UNVERIFIED]** — 제공된 법령 발췌 제26조.

**서버 경유 구매 이벤트**  
철회 후에도 서버 수신기가 새 벤더로 구매 이벤트를 보낼 수 있다면, 화면·SDK OFF와 다른 경로가 남아 있는 것이다. 실제 로그가 없으므로 “보내고 있다”고 단정하지 않는다. “안 보내고 있다”고도 단정하지 않는다. 정책 방안은 거부한 기기·웹·앱에 대해 다른 방식으로 맞춤형 광고용 온라인 식별자를 만들거나, 디지털 지문 등으로 차단을 우회하지 말라고 한다. 이는 **식별하지 않는 처리** 쪽의 사후 통제 **권고** 아래에 적혀 있다. 법정 금지 조문으로 바꾸지 않는다. 다만 서버 포워딩이 철회를 우회하는 실무 경로인지는 출시 전에 로그로 가려야 한다.  
**[공식 실무자료] [UNVERIFIED]** — 같은 정책 방안 PDF 26쪽 대응 발췌(문서 −22쪽).

**벤더 “suppression 적용 완료”**  
대상 식별자(또는 가명키) 범위, 적용 목적(광고 최적화·측정·하위 파트너), 적용 시각이 없으면 제26조제4항 감독 자료로 쓰기 부족하다. 회신 문장만으로는 신규 SDK 초기값, 서버 포워딩, 벤더 쪽 목록이 같은 철회 상태를 가리킨다고 볼 수 없다.

**국외이전**  
제28조의8은 국외 제공(조회 포함)·처리위탁·보관을 “이전”으로 보고, 동의·계약 이행을 위한 위탁·보관 시 처리방침 공개 또는 통지 등 예외를 둔다. 새 벤더 저장·지원 접근·백업 지역은 이번 사실에 없다. 해당성 미확인.  
**[공식 원문 스냅샷] [UNVERIFIED]** — 제공된 법령 발췌 제28조의8.

생성형 AI 안내서는 광고 SDK를 직접 규율하지 않는다. 기업용 계약에서 재이용·학습 금지, 수탁자 명시, 삭제 요청 시 파기를 계약으로 두라는 **권고·예시**로만 본다. 안내서 벤더 표의 “연 1회 감사” 등은 2025.8 상품 스냅샷이며 이 광고 벤더 사실이 아니다. PDF 50쪽 체크리스트는 색이 없어, 항목을 전부 법적 의무로 보지 않는다.  
**[공식 실무자료] [UNVERIFIED]** — 「생성형 인공지능(AI) 개발·활용을 위한 개인정보 처리 안내서」(2025.8) PDF 27–28, 50쪽 대응 발췌.

## 3. 광고 철회와 성능 계측을 나누는 기준

이번 점검에서 성능 계측은 **개인·기기 식별자 없이, 재식별할 수 없는 집계만, 내부 시스템에서만** 처리하고 **외부 벤더 전송이 없다**고 확인됐다.

정책 방안의 판단 사례는 이렇게 나눈다.

- **사례 ①:** 이용자 식별자를 매개로 행태정보를 회원정보와 결합·이용하면 개인정보.  
- **사례 ②:** 랜덤 식별자라도 행태정보에 명백한 개인정보가 있거나 누적·결합으로 식별 가능성이 생기면 개인정보일 가능성이 높음.  
- **사례 ③:** 랜덤 식별자이고 행태정보에 개인정보가 없으며, 시간·비용·기술을 합리적으로 볼 때 다른 정보와 쉽게 결합해 특정 개인을 알아볼 수 없으면 개인정보로 볼 수 없음.

식별 처리(①·②)면 사전 동의 등 적법 요건이 필요하고, 식별 가능성이 없는 정보(③)면 그 상태로 처리해야 한다.  
**[공식 실무자료] [UNVERIFIED]** — 같은 정책 방안 PDF 22쪽 대응 발췌(문서 −18쪽).

식별하지 않고 처리하려면 **개인정보 시스템과 행태 시스템을 분리하고 매칭키를 두지 않는 것**이 의무로 적혀 있다. 투명성(처리방침 공개, 맞춤형 광고 i 표시)과 사후 거부 버튼은 **권고**다. 권고를 법정 점검 주기나 필수 서식으로 올리지 않는다. 맞춤형 **광고**와 맞춤형 **정보추천**도 정책이 구분한다. 내부 성능 집계는 둘 다 아니다.  
**[공식 실무자료] [UNVERIFIED]** — PDF 25–26쪽 대응 발췌(문서 −21∼22쪽).

정리하면,

1. **광고 SDK·구매 이벤트·벤더 전송**은 철회 대상 후보. 화면 OFF + SDK OFF + 서버 미전송 + 벤더 suppression이 같은 식별자·목적·시각에 맞아야 한다.  
2. **내부 성능 집계**는 이번 사실 기준으로 사례 ③ 쪽에 가깝다. 광고 철회가 자동으로 이 집계를 끄거나 지우라는 근거는 이번 번들에 없다.  
3. 두 축을 같은 키로 붙이거나, 집계 쪽에 광고 식별자를 심으면 사례 ①·②로 넘어갈 수 있다. 결합이 없다는 점을 설정·로그로 유지한다.  
4. “모든 보존 데이터 즉시 삭제”는 제21조(파기) 본문이 이번 법령 발췌에 없어 **전면 즉시 파기 의무로 확정할 수 없다.** 광고 목적 식별 데이터의 이용 중단·벤더 전파와, 내부 비식별 집계와, 다른 법령상 보관이 있을 수 있는 항목은 표로 나눈다.

## 4. 남은 확인 (출시 전 가림)

사실관계가 비면 결론을 올리지 않는다.

1. **구매 이벤트 페이로드:** 광고ID, 회원키, 주문번호, 이메일, 디바이스ID 등 포함 여부. 있어야 제15조 목적·항목과 정책 사례 ①·②를 확정할 수 있다.  
2. **서버 실전송 로그:** 철회 전후, 신규 SDK 버전, 수신 엔드포인트, 성공/차단. 수신기 “가능”만으로는 부족하다.  
3. **벤더 suppression 회신 최소 항목:** 요청·변경 ID, 대상 식별자/가명키 범위, 앱·SDK 버전, 처리 목적, 적용 시각, 자기 목적·하위 파트너 범위, 예외·부분 실패, 재처리·재활성화 조건.  
4. **계약:** 위탁 목적 한정, 목적 외·자기 광고 최적화 금지, 재위탁 사전 동의(제26조제6항), 삭제·이용 중단 요청 시 처리. 기업용 DPA 문구는 AI 안내서 권고일 뿐, 이 벤더 계약 내용이 아니다.  
5. **처리방침·수탁자 공개:** 제26조제2항 공개, 홍보·판매 권유 위탁이면 제26조제3항 변경 고지. 정책 방안의 “웹·앱별 수집도구 명칭·제3자·항목·목적·통제방법 공개”는 **권고**(법 제30조제1항 참조). 제30조 본문은 발췌에 없다.  
6. **국외이전:** 저장·백업·해외 지원 접근이 있으면 제28조의8 해당성과 처리방침·통지 여부.  
7. **성능 계측 유지 조건:** 식별자 미사용, 매칭키 없음, 외부 미전송이 빌드·파이프라인에서 그대로인지.  
8. **아동 주이용 앱 여부:** 정책은 14세 미만 주이용 웹·앱에 맞춤형 광고 수집도구 미설치를 **권고**한다. 이번 사실에 없음.

제34조(유출등 통지·신고)는 이번 사안이 “유출등을 알게 된 때”로 정리되지 않았다. 무단 전송이 나중에 확인되면 그때 항목·규모·경로를 따로 본다. 시행령상 신고 기한·규모 기준은 이번 발췌에 없다.

## 5. 출시 전후 조치 (실무 초안)

법적 효과 있는 대외 송부·서명 전 문안이 아니다. 앱팀·개인정보 담당이 손볼 점검 초안이다.

### 출시 전

- 이벤트 목적 표: 광고 개인화 / 광고 측정 / 내부 성능 집계를 이벤트명·파라미터·수신자·법적 근거 후보로 나눈다. 서비스 필수와 광고를 같은 SDK 이벤트로 보내지 않는다.  
- 철회 테스트: 화면 OFF → 신규 SDK 광고 설정 OFF → 서버가 해당 식별자의 광고·구매 이벤트를 새 벤더로 넣지 않음 → 벤더 쪽 목적별 suppression. 한 단계라도 로그가 없으면 출시 블로커로 둔다.  
- 벤더 회신을 위 최소 항목으로 다시 받는다. “적용 완료” 한 줄은 통과 기준으로 쓰지 않는다.  
- 계약에서 자기 목적 광고 최적화가 열려 있으면 제26조제5항 범위 초과 또는 별도 제공 이슈 후보다. 닫혀 있지 않으면 설정만으로 충분하다고 쓰지 않는다.  
- 처리방침·수탁자 목록에 신규 SDK/벤더를 반영할지를 제26조와 권고 공개 항목으로 검토한다. 권고 항목을 필수 법정 서식으로 바꾸지 않는다.  
- 성능 계측 파이프라인에 광고 식별자·회원키가 없는지 한 번 더 본다.

### 출시 후

- 정책 방안은 웹·앱 사업자 CPO에게 수집도구 현황 파악·점검을 **권고**한다(법 제31조제3항 참조). 제31조 본문은 발췌에 없다. **고정 법정 주기나 필수 양식이 아니다.** 교체 직후·포워딩 규칙 변경 때 같은 표를 다시 보는 운영으로 두면 충분하다.  
- 수집도구 변경(엔드포인트, 전송 항목, 하위 벤더)이 있으면 처리방침·수탁자 공개·철회 전파를 같은 변경 티켓에 붙인다.  
- 철회 이후 광고 목적 데이터가 벤더에 남는지, 남으면 이용 중단인지 삭제인지, 예외가 있는지는 항목별로 적는다. 내부 집계는 이 표에 섞지 않는다.
